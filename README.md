# Mini NPU Simulator

## 실행 방법

Python 3.8 이상에서 외부 라이브러리 없이 실행한다.

```bash
python main.py
```

메뉴에서 `1`은 3×3 사용자 입력, `2`는 `data.json` 일괄 분석이다. 기본 데이터 경로는 `data/data.json`이며, 루트의 `data.json` 또는 명령행 인자로 다른 경로를 지정할 수도 있다.

## 구현 요약

- `validate_matrix`가 입력을 숫자형 `N×N` 행렬로 검증하고 변환한다.
- `mac`은 중첩 반복문으로 같은 위치의 값을 곱해 누적하므로 외부 라이브러리를 사용하지 않는다.
- JSON의 `cross`, `x`, `+` 라벨은 각각 표준 라벨 `Cross`, `X`로 정규화한다.
- 패턴 키 `size_{N}_{idx}`에서 크기를 추출해 같은 크기의 필터를 선택한다.
- 두 점수의 차이가 `1e-9` 미만이면 `UNDECIDED`로 판정한다.
- 잘못된 JSON 케이스는 전체 실행을 중단하지 않고 해당 케이스만 `FAIL` 처리한다.
- 성능은 I/O를 제외한 MAC 호출을 크기별 10회 반복해 평균 ms로 측정한다.

## 결과 리포트

실패 케이스는 데이터/스키마 문제, 로직 문제, 수치 비교 문제로 나누어 확인할 수 있다.
패턴 키가 `size_{N}_{idx}` 규칙을 따르지 않으면 스키마 문제로 처리한다.
`input`이 정사각 행렬이 아니거나 필터 크기가 N과 다르면 해당 케이스만 실패한다.
`expected`가 없거나 `+`, `cross`, `x` 이외의 라벨이면 라벨 스키마 문제로 기록한다.
표준 라벨을 먼저 만들기 때문에 대소문자와 `+` 표기가 판정 결과를 흔들지 않는다.
Cross와 X의 점수를 직접 비교하되 차이가 epsilon보다 작으면 임의로 승자를 선택하지 않는다.
따라서 `UNDECIDED`가 expected와 다르면 계산 오류가 아니라 정의된 비교 정책에 따른 FAIL이다.
실패가 0개라면 키/행렬/라벨 검증을 통과했고 정규화와 epsilon 정책이 expected와 일치했다는 뜻이다.
MAC은 각 행과 열을 한 번씩 방문해 총 N²개의 곱셈을 수행한다.
그러므로 공간을 제외한 시간 복잡도는 `O(N²)`이며 연산 횟수 표의 9, 25, 169, 625와 연결된다.
행렬 크기가 커질수록 평균 시간도 대체로 N²에 비례해 증가하는지 성능 표로 확인할 수 있다.

## 재현성

모드 1에서 십자가 필터와 X 필터를 입력하면 각각의 MAC 점수, 10회 평균 시간, A/B/UNDECIDED 판정이 출력된다.
모드 2에서는 각 패턴의 Cross/X 점수와 판정, expected 비교, 전체 PASS/FAIL 요약, 3×3·5×5·13×13·25×25 성능 표가 출력된다.
행/열 수나 숫자가 잘못된 사용자 입력은 안내 후 해당 단계에서 재입력한다.
JSON의 크기 불일치·누락·잘못된 라벨은 프로그램을 중단시키지 않고 케이스 단위 FAIL로 남긴다.
